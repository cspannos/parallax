## Known gaps (v1 prototype)

The gaps known when the v1 prototype was frozen (2026-11-06). Struck-through rows were fixed before the freeze; earlier fixes include client-injected `AdvanceHeight` (ADR 0033), the unkeyed native book index hash (ADR 0032), and per-receipt roots in consensus replay (ADR 0032).

| Area | Gap | Notes |
|---|---|---|
| Hardening | ~~No rate limits on the cert server, the gossip handshake or the PQ tunnel handshake.~~ **Fixed 2026-11-06:** `consensus_adapter::limits`: per-source-IP token bucket, a cap on concurrent connections, and a 5 s deadline for unauthenticated peers on all three listeners; a server-wide `RECOLLECT` budget (32 burst, 16/s) plus a per-height resend gap. | ADRs 0031 / 0030 / 0034 |
| Hardening | ~~The signed-intent signature table (`auths`) grows if signed intents never decide.~~ **Fixed 2026-11-06:** the leak was replays of already-decided intents (the log dropped the intent but kept its signature). A signature is now kept only when the log accepts the intent as newly pending, so the table never exceeds the pending set. | ADR 0033 |
| Throughput | Signed hybrid orders keep up to ~1.5k per height; larger waves split across heights (180 ms admission grace). | Per-connection key cache; retune admission; ADR 0033 |
| Crypto | `ml-dsa` 0.1 / `ml-kem` 0.3 are pre-1.0 and unaudited; validator keys come from seeds; no HSM (Q-CRY-6). | ADR 0030 |
| Proving | A loaded 10k height is ~3.5–4 CPU-hours. Real-time settlement needs GPU / distributed provers (paused). Production commitments in SHA-256 would save ~17% more cycles. | ADRs 0028 / 0029 / 0032 |
| Scale | No WAN or 50–100-validator measurement; the bandwidth at n=100 is a projection. | ADRs 0030 / 0031 |
| Throughput | Decided throughput plateaus ~60–100k orders/s on one host; per-input intake bookkeeping (~2.5 µs) and replays cost more than matching (~1.2 µs). Bigger heights only add latency. | [batch-size](benchmarks/batch-size.md) |
| Engine | ~~No protocol path inserts `AdvanceHeight`, so order expiry never fires under consensus.~~ **Fixed 2026-11-06:** from height 2, the sealed `I(h)` starts with `AdvanceHeight { to: h }` (`IntentLog::tape`), so engine height tracks consensus height and `input_commitment` and `π` cover the advance.
